## 二、架构总览 (1分钟)

**画面: Agent 构成页 (/agent-build) — 5层阶梯**

> 整个系统的架构可以分成五层来看：
>
> **第一层——原子能力单元。** Python 函数实现的具体能力：知识库搜索、题目生成、进度分析等 9 个工具。还有 jieba 分词、bge-m3 向量嵌入、BGE Reranker 精排这些基础模块。
>
> **第二层——自动化流程。** 把原子单元串成管道。比如 RAG 检索管道：分词→BM25→向量召回→RRF融合→Reranker→Top-5，六个步骤自动化完成。知识同步管道也是：检测文件变更→增量分块→嵌入→存 ChromaDB。
>
> **第三层——对话机器人。** 在流程上加对话界面和记忆。Flask+Jinja2 服务端渲染 + 11 个 API Blueprint。Session 管理带 2 小时 TTL 自动回收。SSE 流式输出实时推送。
>
> **第四层——智能体。** 这是最核心的一层。手写 ReAct 循环，Thought→Action→Observation→Final。9 个工具，本地 LLM 通过 Ollama 原生 function calling 驱动。对话历史太长时用 qwen2.5:0.5b 自动压缩。
>
> **第五层——安全约束。** max_steps=6 防无限循环，Session TTL 自动清理，错误优雅降级不崩溃，模型切换白名单。

**关键信息:** 五层渐进 / 每层对应本系统具体实现 / 不是套壳

## 三、核心功能演示 (3分钟)

### 3.1 知识库智能检索 (/knowledge)

**画面: 知识库页面，搜索 "反向传播"**

> 知识库有 4,000+ 篇文档，包括 25 个技术领域的闪卡、12 篇 AI 论文、55 张方法论卡片。
>
> 搜索不是简单的关键词匹配——背后是 BM25 稀疏检索 + 向量语义检索的混合管道，两路结果用 RRF 融合，再经 BGE Reranker 精排，最终返回 Top-5。
>
> 当前 Hit Rate@5 是 80%，MRR 0.71。还在持续优化中。

**操作:** 搜索一个中文词 → 展示结果 → 点开一篇

### 3.2 智能训练器 (/trainer)

**画面: 训练器页面，做一道选择题**

> 训练器有 162 道选择题、244 张闪卡、13 道编程题。间隔重复调度（SRS）控制复习节奏。
>
> 做题不再自动跳转——用户可以停下来看解析。做错了会追问原因：是猜的、不会、还是粗心？这个反馈回路直接增强薄弱点诊断精度。

**操作:** 做一题 → 故意答错 → 展示错因选择 → 点"问AI教练"

### 3.3 AI 对话 (/ — 右侧 AI 面板)

**画面: 右侧 AI 面板，问 "什么是反向传播"**

> AI 面板集成了完整的 Agent 能力。收到问题后：
> 1. Thought: Agent 先思考——"用户问反向传播，先搜知识库"
> 2. Action: 调用 search_knowledge 工具
> 3. Observation: 拿到检索结果
> 4. Final: 基于检索结果生成回答
>
> 而且不是等 15 秒干看——SSE 流式输出实时推送每一步。

**操作:** 发送消息 → 展示思考过程展开 → 展示工具调用步骤

### 3.4 其他页面快速过

> 简历页面支持 AI 审阅和要点提炼。模拟面试支持语音交互和实时反馈。
> 费曼教练强制你用最简单的语言解释概念，发现理解盲区。
> 更新日志页面记录每个版本的改动、数据指标和路线图进度。

**操作:** 快速切 2-3 个页面展示

## 四、技术难点与解决过程 (2分钟)

**画面: 切到 debug-report.md 或口头讲述**

> 整个开发过程中遇到了 26 个记录在案的问题，其中 6 个是严重级别的。我挑几个有代表性的讲：

### 难点 1: Agent 首次调用慢 (~9秒)

> **问题:** LangGraph + ChromaDB + sentence-transformers 的导入和模型加载在首次调用时发生，用户要等 9-12 秒。
>
> **解决:** API 路由用 lazy import（请求到了才加载重依赖），LLM/BGE 模型单例模式。首次延迟可以接受，后续 ~3s。

### 难点 2: API Key 热更新不生效

> **问题:** 用户在设置页改了 API Key，但 Agent 端点仍然报"Key 未配置"。
>
> **根因:** 7 个文件用了 `from config import API_KEY`，在 import 时捕获了字符串值——一个典型的 Python 反模式。后续 `config.API_KEY = new_key` 不会传播到已导入的模块。
>
> **解决:** 全部改为 `import config` + 请求时读取 `config.API_KEY`，延迟求值。

### 难点 3: 本地模型 Ollama function calling 兼容

> **问题:** 本地模型 (llama3.1:8b) 走 Ollama `/api/chat` 做 tool calling，但 Ollama 的 API 格式和 LangChain 的 AIMessage 不兼容。三个坑：`.type` 属性缺失、`isinstance()` 检查失败、`arguments` 字段 Ollama 要求 JSON Object 而非 JSON String。
>
> **解决:** 手写 `_FakeAIMessage` 兼容层 + 4 处 `isinstance` 检查改为 `hasattr` 回退 + arguments 字段格式适配。

### 难点 4: RAG 检索精度迭代

> 第一版纯向量检索，中文语义匹配不好。第二版加 BM25 混合检索 + RRF 融合，Hit Rate 从 60%+ 提升到 76.67%。第三版加 BGE Reranker 精排，再到 80%。
>
> 每一步都有量化评估数据支撑，不是凭感觉调参。

## 五、Agent 构成深度展示 (2分钟)

**画面: Agent 构成页下半部分——"一句话的旅程"管道动画**

> 我来用一个具体例子展示整个处理管道——用户输入"CNN是什么"：
>
> 1. **用户输入** — 右侧 AI 面板发送消息
> 2. **jieba 分词** — "CNN" / "是" / "什么"，提取关键词
> 3. **BM25 检索** — 基于词频的稀疏检索，找到精确匹配的文档
> 4. **bge-m3 向量化** — 查询文本 → 1024 维向量
> 5. **ChromaDB 搜索** — 余弦相似度在 4,000+ 篇文档中找语义相近的内容
> 6. **RRF 融合** — BM25 和向量结果按 0.4/0.6 权重融合排序
> 7. **Reranker 精排** — Cross-Encoder 对粗召回结果重新打分
> 8. **LLM 生成** — 拼接检索上下文 + 用户问题，发给 LLM
> 9. **流式输出** — SSE 逐字推送回复到前端
>
> 每一步都有具体的代码实现，不是一个黑盒的"调用 ChatGPT"。

**关键信息:** 可观测 / 每步透明 / 不是黑盒调API

## 六、模型切换能力 (1分钟)

**画面: 顶栏模型切换下拉**

> 系统支持本地和云端两种 LLM 模式，可以随时切换：
>
> **本地模式:** Ollama 运行开源模型（如 qwen3），完全离线，零 API 费用。适合日常开发和测试。
>
> **云端模式:** DeepSeek API（deepseek-v4-flash），速度快、质量高，适合演示和生产。
>
> 切换不需要改配置文件或重启服务器——顶栏下拉直接切，即时生效。模型配置持久化存储，重启后自动恢复上次选择。
