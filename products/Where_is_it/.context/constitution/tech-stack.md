# Where_is_it — 技术栈

## 状态：待定

技术选型将在 Phase 1 结束后、Phase 2 开始前确定。选择依据：

## 核心需求（约束技术选型）

1. **低编码成本**：交互路径最短（理想：1 动作完成记录）
2. **事件边界检测**：需感知"即将出门/换场景"——移动端传感器（GPS/蓝牙/加速度计）或桌面端固定位置（摄像头？磁传感器？NFC 标签？）
3. **触发可靠性**：提醒必须在关键时刻到达（推送通知 / 桌面弹窗 / 音频）

## 候选方向

- **移动端**（App/小程序/pwa）：传感器丰富、随身、推送原生。劣势：开发周期长
- **桌面端 + 物理标签**（NFC/二维码贴在门口）：简单可靠、不依赖手机。劣势：只能覆盖家门
- **纯软件**（CLI/Web/小工具 + 手动触发）：最快落地。劣势：触发靠自觉，等于没解决"编码失败"

## 暂不决定

等 Phase 1 个人数据采集 + 与用户讨论后选定。
