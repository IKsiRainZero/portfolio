# Where_is_it — 架构

## 问题域

**核心问题**：前瞻记忆（prospective memory）失效——"记得要做某事，但在正确的时间/地点没想起来"。

三个关键机制导致物品丢失：

1. **编码失败**（最根本）：放东西时注意力不在"放置"这个动作上，记忆根本没写入。Schacter: 问题出在"注意力与记忆的接口"，不是记忆检索。
2. **事件边界效应**（Doorway Effect）：穿过门、合上书、关上门——这些"结束"信号让大脑把上一段记忆归档，连带其中的意图也一起封存。在认知负荷下加剧。
3. **例行中断**：固定流程被打乱的那天最容易忘东西（忘带伞 = 出门流程没触发"检查天气→带伞"）。

## 设计原则

从研究推导出的有效策略（按效果排序）：

| 策略 | 机制 | 可工程化程度 |
|------|------|-------------|
| 实现意图（If-then） | 预先绑定情境→动作 | 高 |
| 固定位置（designated spot） | 消除检索需求 | 高 |
| 外部线索（cue placement） | 环境触发提醒 | 高 |
| 出声复述（verbalize） | 强制编码 | 中 |
| 想象后果（unitisation） | 丰富编码痕迹 | 低 |

系统应覆盖**完整时间线**：放置时（编码）→ 静止时（库存）→ 移动前（检索）

## 模块设想（待确定技术栈后细化）

```
编码层 — 记录"什么东西放在哪"，降低编码门槛
库存层 — 当前所有物品位置状态
触发层 — 识别事件边界（出门/换场景），在遗忘发生前提醒
```

## 工作流

1. Phase 1：吃透问题域（研究文献 + 个人数据采集）
2. Phase 2：最小可用系统（核心链路：记录→查询→提醒）
3. Phase 3：打磨（降低摩擦、提高触发精准度）
